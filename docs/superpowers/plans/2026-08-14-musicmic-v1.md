# MusicMic V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows 11 x64 WPF utility that copies one selected application's audio and a selected microphone to VB-CABLE without modifying the application's normal playback path.

**Architecture:** A C++20 native engine owns Windows Core Audio capture, mixing, endpoint rendering, and recovery, exposed through a narrow C ABI. A .NET 10 WPF application owns the compact UI, persisted settings, themes, tray behavior, logging, and engine state presentation. A managed domain layer makes the playback-routing invariant, state transitions, settings, and reconnection policies executable in unit tests independent of audio hardware.

**Tech Stack:** .NET 10, C# WPF, C++20, CMake, WASAPI/Core Audio, xUnit, WiX Toolset.

**Spec:** `SPEC.md` (imported from the supplied MusicMic V2 specification before implementation).

## Global Constraints

- Target Windows 11 x64; app is C# WPF and native audio is C++20/WASAPI.
- Capture only the selected process using process-loopback; never change the selected application's endpoint, volume, mute state, playback, or the Windows default endpoint.
- V1 writes the stereo 48 kHz float mix to the separately installed VB-CABLE `CABLE Input` render endpoint; it never ships a custom driver.
- Expose exactly source selector, microphone selector, two percentage volumes, status, start/stop, theme settings, and minimal tray controls.
- Persist local settings and rotating text logs only; do not record audio or transmit telemetry.
